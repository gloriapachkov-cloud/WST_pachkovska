# RE:BELLE — лабораторні №7–8 (Monorepo)

Це продовження **оригінальних лабораторних №4 (React/Vite) та №6 (Electron)**. Мобільна лабораторна №5 не включена в запуск, бо методичка №7–8 перевіряє веб- та десктопний клієнти.

## Запуск (Windows / VS Code)

1. Розпакуйте ZIP та відкрийте **кореневу теку REBELLE_Lab7_8_Ready** у VS Code.
2. У терміналі виконайте `npm install` (потрібен Node.js 20.19+ або 22.12+).
3. Перевірка спільного ядра: `npm run test:core`.
4. Перевірка всіх пакетів: `npm test`.
5. Вебверсія: `npm run start:web` — відкрийте адресу з термінала (зазвичай http://127.0.0.1:5173).
6. Десктоп: в іншому терміналі `npm run start:desktop`.
7. Збірка вебверсії: `npm run build:web`.

## Архітектура

- `packages/core/index.cjs` — незалежні від платформ правила перевірки записів, пошук, сортування, додавання, видалення, перемикання стану та перевірка конфлікту часу.
- `packages/web` — збережено React/Vite/Tailwind інтерфейс із лабораторної №4; адаптер `localStorage` у `src/App.jsx`.
- `packages/desktop` — збережено Electron інтерфейс, реєстрацію, ролі, каталог послуг, майстрів і JSON-збереження з лабораторної №6. `main.js` використовує спільне ядро, `preload.js` залишає ізольований API.
- `packages/*/tests` — тести пакетів; `packages/core/core.test.cjs` — 16 тестів ядра.

## Важливо

Веб- та десктопний клієнти зберігають дані **незалежно**: `localStorage` і `notes.json`. Інтерфейси залишаються такими, як у попередніх лабораторних, тому відрізняються за набором полів та можливостей. Спільні правила застосовуються до сумісних полів; це не повна уніфікація функціональності двох застосунків.

Для демонстрації спільності змініть `MAX_CLIENT_LENGTH` у `packages/core/index.cjs`, запустіть тести та перевірте реакцію веб- й десктопної версій на довге ім’я. Після демонстрації поверніть початкове значення 80.

У десктопі демо-акаунти з попередньої лаби: `admin / Admin2026!` і `master / Master2026!`. Це лише локальні демонстраційні дані, не використовуйте їх у реальному продукті.


## Єдине джерело логіки для лабораторних №7–8

**Редагуй лише `packages/core/index.cjs`.** Файл `packages/core/index.mjs` генерується автоматично командою `npm run sync:core`. Команди `npm test`, `npm run start:web`, `npm run start:desktop` і `npm run build:web` запускають генерацію перед виконанням. Це дає спільну реалізацію правил для браузера (ESM) та Electron (CommonJS).

### Демонстрація зміни правила

1. Зроби скриншоти успішних тестів і двох інтерфейсів.
2. В `packages/core/index.cjs` зміни `MAX_CLIENT_LENGTH = 80` на `MAX_CLIENT_LENGTH = 40`.
3. Перезапусти вебсервер і Electron (щоб перечитати модулі).
4. Перевір ім'я довше 40 символів у вебверсії. Для Electron перевірка довжини імені спрацює лише там, де форма передає ім'я у `validateBooking`; за потреби демонструй результат безпосередньо через тест ядра.
5. Поверни `80`, виконай `npm test`.

**Увага:** у десктопному застосунку валідація може застосовуватися до інших полів, ніж у вебформі; це залежить від потоку авторизації та створення записів.
