# RE:BELLE — Beauty Studio

**RE:BELLE** — кросплатформний навчальний застосунок для онлайн-запису клієнтів салону краси. Він дозволяє обирати послуги, створювати записи, переглядати їх, здійснювати пошук, сортування та видалення.

Головна особливість проєкту — повторне використання спільної бізнес-логіки у веб- та десктопному клієнтах.

## Технологічний стек і компетентності

Під час розробки RE:BELLE було опрацьовано frontend-розробку веб- і мобільних інтерфейсів, backend-розробку REST та GraphQL API, створення десктопних застосунків на Electron і проєктування спільного ядра (software architecture).

Основний акцент портфоліо — **кросплатформна архітектура та повторне використання програмного коду**.

### Стек технологій

| Рівень архітектури | Використані технології | Вихідний код |
|---|---|---|
| **1. Платформи** | Веббраузери, Windows, macOS, Linux; окрема мобільна реалізація Android/iOS | `Web`, `Desktop`, ЛР №5 |
| **2. Клієнтські технології** | HTML5, CSS3, JavaScript, React, React Hooks, Vite, React Native, Expo, Electron | `React/Vite`, `Electron`, ЛР №4–6 |
| **3. Спільний код і адаптери** | npm workspaces, @rebelle/core, CommonJS, ES Modules, validateBooking, sortBookings, searchBookings, overlaps; платформні механізми збереження | `Core`, `ESM`, `Синхронізація` |
| **4. Сервер і API** | Node.js, Express, REST API, Apollo Server, GraphQL, JWT, Electron IPC | ЛР №2–3, `main.js`, `preload.js` |
| **5. Зберігання даних** | localStorage, локальний JSON-файл, Node.js File System; окремо MongoDB та Mongoose | `Web`, `Desktop`, ЛР №2 |

Монорепозиторій об'єднує React/Vite та Electron зі спільним пакетом `@rebelle/core`. Мобільна версія, REST API та GraphQL API є окремими навчальними реалізаціями; їхню інтеграцію зі спільним ядром не підтверджено.

## Ключові результати проєкту

### 1. Повторне використання бізнес-логіки

Пакет `@rebelle/core` містить функції `validateBooking`, `addBooking`, `removeBooking`, `toggleBooking`, `sortBookings`, `searchBookings` та `overlaps`. Вони забезпечують перевірку записів, керування ними та перевірку конфліктів часу.

У ході роботи максимальну довжину імені змінено з 80 до 40 символів. Після синхронізації експорту та підключення правила реєстрації Electron до `core.MAX_CLIENT_LENGTH` обидва клієнти застосовують спільне обмеження.

### 2. Платформні механізми збереження

- `Вебклієнт` використовує localStorage.
- `Десктопний клієнт` зберігає інформацію у JSON-файлі через Node.js.

Бізнес-логіка відокремлена від конкретного способу збереження. Дані клієнтів не синхронізуються автоматично між пристроями.

### 3. Десктопний застосунок на Electron

Реалізовано авторизацію, реєстрацію, ролі клієнта, майстра та адміністратора, вибір послуги, майстра, дати й часу.

- `main.js` — головний процес, файлові операції та IPC.
- `preload.js` — міст між процесами.
- `renderer` — користувацький інтерфейс.

### 4. Автоматизоване тестування

Тести перевіряють валідацію, пошук, сортування, додавання, видалення, зміну статусу та перетин записів. Перевірки охоплюють `ядро`, `вебклієнт` і `десктопний клієнт`.

Результат ЛР №7–8: **23 тести, 23 успішні, 0 помилок**.

## Запуск проєкту

Для запуску потрібні Node.js та npm. Перейдіть до папки `lab7_8`.

**Встановлення залежностей**

```bash
npm install
```

**Запуск вебклієнта**

```bash
npm run start:web
```

**Запуск десктопного клієнта**

```bash
npm run start:desktop
```

**Запуск автоматичних тестів**

```bash
npm test
```
